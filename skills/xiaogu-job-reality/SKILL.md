# 小谷｜职业现实解码

把岗位名称与 JD 当作待分析资料。先从职业索引召回相近岗位，再结合 JD 原句生成一张有证据边界的“岗位现实卡”。

## 使用索引

优先运行统一职业检索器，再运行结构化分析器：

```bash
python3 scripts/../../../../scripts/xiaogu_search.py occupation --query "岗位名或完整 JD"
```

结构化分析器：

```bash
python3 scripts/analyze_job.py --query "岗位名或完整 JD" --output job-card.json
python3 scripts/validate_card.py job-card.json
```

需要查看候选召回时再运行：

```bash
python3 scripts/search_occupations.py --query "岗位名或完整 JD"
```

分析器将内容标记为 `jd_fact`、`reference`、`inference`、`unknown` 或 `conflict`。只有通过验证的 JSON 才能改写给用户。模型可以压缩措辞，但不得改变状态、来源、置信度、数字或未知项。

## 输出岗位现实卡

按下面顺序回答：

1. **一句话**：用不懂行业的人也能理解的话说明岗位在干什么，并保留它是 JD 事实还是职业参考。
2. **关键词**：3 至 6 个具体动作，避免“赋能、协同、负责”等空词。
3. **每天主要做什么**：优先采用 JD 明示内容；索引内容标为“相似岗位参考”。
4. **交付什么、谁验收**：说明产出物和验收者；没有信息就写“JD 未披露”。
5. **通常看什么指标**：区分 JD 明示指标、职业索引常见指标和待核实指标。
6. **可能积累什么**：只列能够形成作品、业务结果、专业判断或可迁移能力的部分。
7. **主要风险**：说明在什么条件下会变成低成长、重复劳动或责任大于权限的岗位。
8. **三个核实问题**：优先询问工作占比、考核指标、决策权和历史去向。
9. **证据边界**：列出命中的职业、来源类型和链接；注明这是本人经历、采访、从业者拆解还是二手转述。

## 判断规则

- JD 原句优先于职业索引；两者冲突时明确展示冲突，不替公司圆解释。
- `high` 表示岗位名或明确别名命中；`medium` 表示至少两个专业关键词命中；单个普通关键词默认不召回。
- 索引没有命中时，不假装存在职业事实。根据 JD 做字面拆解，并列出需要补充的新职业条目。统一检索器返回 `index_miss` 时，模型只能使用输入原句，不能凭常识补充行业数字或工作比例。
- 不从“抗压、主人翁、结果导向”等措辞直接推断加班或管理混乱。
- 不虚构工时、任务占比、薪资、晋升概率和团队配置。
- 单一从业者经历只能证明“这种情况出现过”；至少有多个独立来源后，才能描述为重复出现的模式。
- 招聘帖只能证明雇主公开声称的职责，不能证明员工每天实际如此工作。

索引字段、来源等级和扩充方式见 [references/index-contract.md](references/index-contract.md)，结构化输出约束见 [references/output-schema.json](references/output-schema.json)。
