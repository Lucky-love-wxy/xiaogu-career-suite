# 职业索引契约

`occupations.json` 保存可复用的职业基线，不保存对某一家公司的无依据判断。

## 必填字段

- `id`：稳定英文标识。
- `name`、`aliases`、`family`：标准名称、常用别名和职业族。
- `parent_id`：职业层级中的直接父节点；父节点必须存在于 `taxonomy.json` 或职业索引中。
- `plain_language`：一句话人话解释。
- `keywords`、`daily_work`、`deliverables`、`metrics`：具体动作、日常任务、交付物和常见指标。
- `growth`、`risks`、`questions`：可迁移能力、条件化风险和核实问题。
- `evidence`：来源类型、标题、URL 和适用范围。

## 来源等级

从强到弱参考：

1. 多名从业者的独立采访或多个相互独立的本人经历。
2. 单名从业者的具体经历或从业者对工作流程的拆解。
3. 媒体二手转述、课程机构案例。
4. 招聘 JD。它只证明雇主公开要求，不证明实际工作体验。

来源等级只表示对“实际工作”的支撑强弱，不代表文章观点必然正确。

## 运行时契约

- `analyze_job.py` 负责匹配职业、保留 JD 原句、标记未知项和显式冲突。
- `validate_card.py` 负责逐字核验 JD 事实、职业索引引用和数字来源。校验失败时不得交给模型改写。
- 模型只能改写通过校验的结构化卡片；不得新增事实、数字、来源或确定性。
- 索引未命中时仍保留 JD 中的陈述句；职业基线标为未知，不用相邻职业替代。
- `output-schema.json` 是输出字段与状态白名单，`taxonomy.json` 是职业层级的唯一结构来源。

## 扩充规则

新增职业前先检查别名，避免把同一工作重复建档。新的来源先追加到 `evidence`；只有它改变了已有结论时，才更新职业基线。保留矛盾，不把不同公司、职级和行业强行平均。
