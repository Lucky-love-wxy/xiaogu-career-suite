# 小谷｜简历

把简历当作“真实经历的岗位化表达”，不是把 JD 里的词换进简历。先读取候选人事实主档和目标岗位，再做逐条证据匹配。

## 必须遵守

1. 每个项目描述、数字、技术名词和结果都要能回到 `candidate-profile.md`、作品链接、项目文档或用户当前确认的材料。
2. 没有证据的内容只能写成“待确认”，不能变成简历事实；不能为了看起来完整而补数字、团队规模、增长率、职责范围或获奖情况。
3. JD 里的要求只能用来决定排序和表达角度，不能当作候选人已经具备的能力。
4. 先用岗位检索和 JD 解码结果确定重点，再写简历；没有命中职业索引时说明岗位基线未知。
5. 输出岗位版本时保留 `job_id`、版本号、创建时间和证据 ID，方便回退与复核。

## 工作步骤

1. 读取目标岗位 `jobs/raw/<job_id>.json` 和 `jobs/decoded/<job_id>.json`。
2. 读取候选人事实主档，只取 `candidate_confirmed`、`written_material` 等已确认内容。
3. 建立“岗位要求 → 候选人证据”的对照表，区分已匹配、部分匹配、缺证据和不匹配。
4. 生成 3 至 6 条项目/经历 bullet。每条 bullet 尽量包含动作、对象、结果；结果未知就不强写结果。
5. 生成一段岗位定制摘要和待补证据清单。
6. 用 `scripts/validate_resume.py` 校验后再交付。

## 输出顺序

- **岗位重点**：来自 JD 的明确要求与黑话翻译。
- **证据匹配**：每项要求对应哪些真实经历。
- **岗位版摘要**：不超过 120 字，事实优先。
- **经历 bullet**：每条带 `evidence_ids`。
- **仍缺什么**：明确需要候选人补充的事实。
- **不能写的内容**：列出没有证据的诱人表述，防止误用。

示例 JSON 结构见 `_xiaogu-runtime/references/workspace-contract.md`；验证器要求每条 bullet 至少有一个证据 ID，并标记 `confirmed` 或 `needs_confirmation`。
