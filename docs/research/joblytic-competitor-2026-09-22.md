# 效招 Joblytic 竞品调研

调研日期：2026-09-22

调研对象：https://xzjobs.cn/

## 一句话结论

效招 Joblytic 做的是面向大学生校招的 AI 求职工作台。它以个人简历和求职目标为起点，把岗位发现、匹配判断、简历定制、网申辅助、投递进度、求职文书和 AI 陪练放到同一个产品中。

它的主要竞争力不是某一个提示词，而是把整个求职过程变成可视化、可连续操作的产品流程。

## 已公开展示并可核对的功能

| 模块 | 具体实现 | 公开页面显示的状态 |
|---|---|---|
| 岗位看板 | 实习/校招切换，搜索与筛选，展示城市、到岗方式、实习时长、每周天数、转正机会和毕业年份；提供收藏、岗位详情和投递入口 | 有公开交互样例 |
| AI 匹配 | 给岗位显示总体匹配分，并按资格要求、岗位方向、技能匹配、经历背景拆分；同时写“适合你的原因” | 有公开样例，评分算法和证据口径未公开 |
| 岗位解读 | “问招招”输出核心判断、能力信号、经历信号和下一步，并支持继续追问 | 有公开样例 |
| 进度管理 | 同一套求职记录可用表格和日历查看；字段包括公司、岗位、城市、进度、时间、提醒、优先级、备注、招聘类型和岗位来源 | 有公开可编辑样例 |
| AI 简历 | 选择目标岗位，显示匹配评估和岗位标签；逐条展示原文与润色后内容，支持恢复原文、再次改写、内容编辑、格式调整、保存以及导出 PDF/DOCX | 有公开交互样例 |
| 求职文书 | 根据岗位 JD、个人经历和写作要求生成投递邮件、自荐信和网申主观题，可选择简历、语言、长度和落款 | 有公开样例；使用个人材料需要登录 |
| 自动网申 | 通过 Chrome/Edge 浏览器插件连接账号和个人资料，识别招聘官网或 ATS 表单并映射字段；验证码、开放题和不确定字段留给用户，最终提交由用户完成 | 明确标记为内测，站点支持范围逐步适配 |
| AI Copilot | 官网展示岗位研究、投递策略、面试准备、问题预测、模拟面试和复盘建议 | 主要是官网演示，未在未登录状态验证完整闭环 |

## 产品流程

1. 用户录入简历、经历和求职偏好。
2. 系统在岗位看板中展示实习或校招机会，并给出匹配排序和解释。
3. 用户收藏岗位，将它放进进度管理。
4. 用户针对目标 JD 生成或修改岗位版简历和投递文书。
5. 用户通过浏览器插件减少招聘官网中的重复填表。
6. 系统在表格和日历中记录投递、笔试、面试、Offer 和提醒。
7. AI Copilot 在岗位研究、面试准备和复盘环节继续给行动建议。

## 商业模式

网站采用免费版加 Pro 会员的模式，并说明所有计划为一次性购买，不自动续费。

- 新用户首周：0.99 元；页面标注原价 9.9 元/7 天。
- 周卡：9.9 元/7 天。
- 月卡：29 元/30 天。
- 校招季全程卡：98 元/180 天。

免费版保留岗位推荐、有限次数的简历润色、求职写作、简历评估、简历导出和进度管理。Pro 主要售卖更高或无限的 AI 使用额度、更多简历存储、短信提醒和新功能优先体验。

## 它解决的核心问题

效招把大学生求职中的两个问题放在一起解决：

第一是信息散。岗位分布在招聘网站、企业官网、公众号和社群中，用户很难统一筛选和跟踪。

第二是动作碎。筛岗位、改简历、写文书、填网申、记进度和准备面试原本散落在不同工具里。效招通过统一个人资料和岗位对象，把这些动作接成一个连续流程。

## 相对小谷 Skill 群的强项

1. 有完整的网页产品界面，不依赖用户理解 Skill 或提示词。
2. 岗位、简历、进度、日历和提醒属于同一个数据系统。
3. 岗位卡片直接提供收藏、详情、投递和 AI 追问入口，行动路径短。
4. 简历提供逐条改动对比、恢复原文和导出，用户容易检查结果。
5. 自动网申把个人资料映射到外部表单，实际减少重复劳动。
6. 价格低、免费版可试用，降低大学生第一次使用门槛。

## 小谷仍然可以形成的差异

1. 小谷强调“JD 明确事实、职业数据库参考、待核实推断、当前未知”分开；效招公开样例更强调匹配分和行动建议。
2. 小谷把行业黑话翻译成可向招聘方核实的问题，这是效招公开功能中没有单独强化的能力。
3. 小谷的职业现实数据库回答“这个岗位通常每天在做什么”，效招更关注“你和这份岗位有多匹配”。
4. 小谷要求简历内容绑定真实经历和证据，不允许为了匹配度补造数字；效招公开演示没有展示 evidence_id 或事实主档校验机制。
5. 小谷的面试复盘要求回到逐字稿原话，区分知识缺口和表达缺口；效招公开页面尚未证明有同等深度的逐字稿溯源闭环。
6. 小谷可以把数据库和 Markdown 资料交给用户自己保存，便于迁移和审计；效招更像封闭的一体化 SaaS。

## 风险和未验证部分

- 官网的“少走 80% 弯路”“每天有数万名同学使用”“支持 90%+ 主流系统”“基于 1.2k+ 真实面经”等属于产品方自述，本次没有获得独立证据验证。
- 岗位匹配的百分比分数没有公开计算方法、训练数据或校准结果，不能把 92% 等同于面试或录用概率。
- 岗位看板公开演示显示 20 个当前可投岗位，但这不能代表登录后的完整岗位库规模。
- 自动网申页面明确写着内测开放中；招聘官网完整支持、常见 ATS 逐步适配、招聘平台部分支持。
- 公开演示可以证明产品交互已经设计和呈现，不能完全证明所有功能在真实账号、真实岗位和所有外部网站上都稳定运行。
- 用户评价、Offer 标识和案例来自官网展示，不能当作独立效果验证。

## 对小谷的产品建议

不建议复制一个功能更多但缺少差异的校招平台。小谷应保留“讲人话、证据分层、先检索后解释”的核心，再吸收以下产品结构：

1. 建立统一的“岗位档案”。每个岗位保存 JD 原文、来源、职业参考、黑话、核实问题、简历版本、面试记录和当前进度。
2. 增加“岗位流水线”。至少显示待分析、待核实、待改简历、已投递、面试中、已结束，并给每一步明确的下一动作。
3. 简历输出增加逐条修改对比、恢复原文和证据入口，而不仅是生成一整份新简历。
4. 用证据覆盖表代替不透明的匹配百分比：岗位要求是什么、候选人有什么证据、证据强不强、还缺什么。
5. 保持最终投递由用户确认。自动填写可以以后做，先不要把自动提交作为核心卖点。
6. 面试后把原问题、原回答、诊断、练习和下一场表现串起来，形成效招公开页面尚未充分展示的长期改进闭环。
