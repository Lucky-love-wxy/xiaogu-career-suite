## 3. 小谷还没有、值得借鉴的点

### 3.1 先判 JD 每条要求有多重要，再看简历（career-ops，两遍法）
- 做法：第一遍只读 JD，给每条要求定重要度；第二遍才读简历，填匹配。第二遍不准回改重要度。
- 原因（原文大意）：模型刚写完「强匹配」，就会倾向于把这条要求也判得重要，同时淡化候选人缺的那些。
- 对小谷：现在的对照表是一遍做完的，大学生简历薄，这种锚定偏差会更明显。

### 3.2 重要度分档并标依据，「推断」封顶（career-ops）
- 用 5 档（critical / high / meaningful / preferred / low_signal），不用 0–100 分。理由：87 和 84 在同一份 JD 上跑两次复现不了。
- 每条标依据级别：`stated`（JD 原话写了必须，附原句）、`structural`（从 JD 结构看得出，比如放在「任职要求」还是「加分项」）、`inferred`（凭行业经验判断）。
- 硬规则：`inferred` 永远不能是最高两档。理由：把候选人缺的东西凭猜测抬成「必须」，用户就会放弃本该投的岗位，这个错比低估更贵。
- 对小谷：大学生最常见的误判就是被 JD 里一堆要求吓退。这条规则直接针对这个问题。

### 3.3 表格裁剪规则（career-ops）
- 最多 12 行，但 critical / high 永远不删。同一档里「没满足的」排在「已满足的」前面，先暴露最重要的缺口。
- 对小谷：控制输出长度，同时不漏关键缺口。

### 3.4 改简历分三档力度（Resume-Matcher）
- nudge：只改措辞，不加 bullet，保持条数和顺序。
- keywords：把 JD 的词换进已有经历，不新增 bullet。
- full：可以展开已有工作，但不能发明新职责。
- 三档共用一套真实性规则：不加原简历没有的技能、数字、公司、职级；原有的技能和奖项不能删。
- 对小谷：用户可以选「轻改 / 中改 / 重写」，每档允许做什么写死在规则里。

### 3.5 简历太薄时先追问，最多 6 个问题（Resume-Matcher enrichment）
- 先识别弱描述：「负责」「参与」「协助」、没有数字、范围不清、没写工具、看不出本人贡献。
- 全简历最多问 6 个问题，每个附示例占位符；用户的回答作为新 bullet 追加，原 bullet 不动；不能发明用户没说的数字。
- 对小谷：目标用户是什么都不会的大学生，「先问再写」比「待确认」清单更好用。

### 3.6 用代码核数字和事实，不只靠 prompt（career-ops）
- 生成的 PDF 里，数字或事实如果在简历原文和用户材料里都找不到，代码直接拦截。
- `cv-facts.json` 里列出允许出现的数字、禁用词（如「世界 500 强」「专利」）、警告词（如「可能」）。
- 对小谷：正好补上「非空 ID ≠ 内容真实」这个缺口，可以扩展进现有的 `validate_resume.py`。

### 3.7 允许判「别投」，人做最终决定（career-ops）
- 总分低于 4.0/5 就明确建议别投，用户可以推翻，系统会记下这次推翻。系统永远不替用户点提交。
- 「哪个方向都不匹配」是合法结论，不硬套最近的岗位类型。
- 口号原文：Apply better to fewer。
- 对小谷：主流程目前是「看懂 → 改简历」，中间缺一个「值不值得投」的判断。

### 3.8 结果回流校准（career-ops `calibrate`）
- 用户记录每次投递的结果（面试 / 拒），脚本统计「分数段 × 面试率 × offer 率」，检查打分能不能预测结果。
- 样本太少就直接写「n 太小」，不把 2/3 算成百分比；只给建议，不自动改打分规则。
- 对小谷：将来有用户以后，用这套办法验证小谷的判断准不准。

### 3.9 国内招聘平台的取数方式（career-ops-china）
- 明确放弃自动爬 BOSS / 猎聘 / 拉勾 / 脉脉，改成用户在自己的浏览器里点一个书签脚本，把已经看到的 JD 结构化发到本地 inbox；登录墙平台让用户截图。
- 能直接抓的只有公司自己的静态招聘页、V2EX、GitHub。
- 对小谷：和小谷已经确认的约束一致（产品服务器读不了脉脉、不冒用身份），而且给了一个可行的替代方式：用户自己捕获 JD。

### 3.10 国内特化的硬红线（career-ops-china）
- 评估前先过红线，命中就跳过：外包 / OD / 派遣、大小周等由用户自己定义。内置 HR 派遣公司识别（人瑞、中智、FESCO、外企德科、万宝盛华、科锐国际等）。
- 内置大厂职级对标表（阿里 P、腾讯 T、美团 L 等）。
- 对小谷：派遣识别对分不清「外包」和「正式」的大学生很有用。

### 3.11 调研有预算上限（career-ops）
- 评估公司和薪资时最多搜 5 次，不准开深度调研、不准派子 agent；查不到就写「不可得」，不准硬凑。
- 对小谷：控制服务器端的 DeepSeek 和搜索 API 成本。

## 4. 适配时要注意的差异
- career-ops 面向有经验、主要找海外岗的人；小谷面向没经验的中国大学生。北极星对齐、薪酬、职级这几块的权重不能照搬。
- career-ops 跑在用户本机的 CLI 里，小谷是服务器上的 Web Agent。「本地优先、不上传」这类隐私设计换了运行环境，要重新想。
- career-ops-china 只有 109 星，是个人 fork，没有被大量用户验证过。
- 本文只读了文档和 prompt，没有运行这些项目，效果未验证。
