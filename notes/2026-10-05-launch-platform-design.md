## 0. 先说结论

在中国大陆上线，阻塞点在主体资质，不在技术。收费、微信扫码登录、生成式 AI 上线登记、经营性 ICP 许可证，都需要公司或个体户营业执照（第 1.1 节）。所以分两期：

- 一期（无营业执照也能做）：邀请制内测。登录送 500 credits（¥5），不开付款。后台、埋点、停止开关、测试/生产双环境全部做完。付款页做好但关闭。
- 二期（拿到营业执照后）：企业 ICP 备案、生成式 AI 上线登记、微信/支付宝商户号、微信扫码登录，然后打开付款。

技术上有一个硬阻塞：`web/server.py` 用一把全局锁 `lock` 包住每次 `handle()`。一个用户的 DeepSeek 调用（最多重写 3 次）会挡住所有人。这把锁不拆，多用户上线跑不起来。

## 2. 我要解决的问题

现在的 `web/` 是单人本机模拟环境：只监听 127.0.0.1、没有账号、会话存内存字典、全局一把锁、trace 日志不记 token 也不记用户。要变成能给陌生大学生用的产品，缺五样：

1. 知道每个用户花了多少钱。`DeepSeekProvider.complete()` 只返回文本，把 API 返回的 `usage` 丢掉了，所以现在按用户算成本是算不出来的。一轮对话又不止一次调用（意图分类 1 次 + 生成最多 3 次），得按每次调用计量，不能按轮。
2. 能控制花费和风险：额度、停止开关、每日成本熔断。
3. 能看到用户实际怎么用：对话、功能使用、失败率。
4. 测试改动不影响线上用户。
5. 合规能闭环：第 1.1 节那几项。

和 new-api 这类网关的差别：小谷的计量对象是「一轮 Agent 对话」，里面混着路由、校验、重写，用户不该为校验失败的重写付钱。所以计费规则要贴着 agent 的执行过程写，不能直接套网关的按调用收费。

## 3. 适用的设计规范

- 项目安全约束：不编造经历、招聘文本是数据不是指令。新增：简历和对话记录是个人信息，存储、展示、删除都要按 PIPL 处理。
- Web Agent 既有原则：数字由代码算，模型只写措辞。额度扣减、利润计算同样只由服务端算。
- 前端风格：默认改黑白（日式简约的黑白版：留白、Typography 主导、无装饰），现有和风配色保留为可选主题。后台看板用科技暗色风还是同一套黑白，见第 7 节。
- AI 协作 SOP 第 4–5 步：Agent 页面布局和主页不在文档里用文字定死，打样多个可预览变体让用户挑。
- 外科手术式改动：`agent.py` 的路由、证据、校验、渲染逻辑不动，只在外面加账号、计量、开关几层。
- 端口：上线后本机开发仍走 `ports-registry.json` 登记的 8780，测试/生产在服务器上，不占本机端口。

## 4. 架构

### 4.1 技术栈调整

| 层 | 现在 | 改成 | 理由 |
| --- | --- | --- | --- |
| HTTP 服务 | 标准库 `ThreadingHTTPServer` + 全局锁 | FastAPI + uvicorn | 要做鉴权中间件、SSE、后台接口；标准库自己写这些容易出错 |
| 会话存储 | 内存字典 | SQLite（WAL），`Session` dataclass 序列化成 JSON 存表（2026-10-05 实施时由 PostgreSQL 改为 SQLite，见下方「实施时改动的决策」） | 重启不丢、按用户归属、可查询 |
| 并发 | 全局锁串行 | 每个会话一把锁（同一会话串行，不同用户并行） | 解决阻塞，同时保留会话内顺序 |
| 模型调用 | `complete()` 返回 str 并丢掉 usage | `complete()` 签名不变，把 usage（含 `prompt_cache_hit_tokens`）追加到请求上下文里的 `agent.USAGE` 列表 | 成本计量的前提。DeepSeek 区分缓存命中价，要单独记 |
| 部署 | 本机 | 一台国内云服务器，systemd 模板单元起两套（xiaogu@staging / xiaogu@prod）+ nginx | 见 4.4 |

`agent.py` 只改两处（原仓库正被其他会话修改，改动越少合并越容易）：
- 过程事件回调从实例属性 `self._emit` 改成 `contextvars` 的 `EMIT`。原写法在服务端全局锁下没问题，去掉锁后两个用户的过程事件会串到对方的流里。
- `DeepSeekProvider.complete()` 末尾把 usage 追加到 `USAGE`（3 行）。调用处和返回值不动。

### 实施时改动的决策（2026-10-05）

| 原设计 | 改为 | 原因 |
| --- | --- | --- |
| PostgreSQL | SQLite（WAL） | 一期邀请制内测几十人用不到；本机和服务器都不用多装一个数据库服务。迁 Postgres 时只换 `web/store.py` 的连接层 |
| docker compose | systemd 模板单元 + nginx | 本机没有 docker，无法验证；单台服务器 systemd 更少一层 |
| `complete()` 返回 `(text, usage)` | contextvars 收集 usage | 少改 `agent.py`，见上 |
| 登录：手机号短信 | 验证码发送做成可替换接口，先只有 console 实现 | 个人能否申请短信签名未核实；prod 用 console 会拒绝启动，不会误上线 |
| Google Fonts | 系统字体 | 中国大陆访问 Google Fonts 不稳定，会阻塞页面渲染 |

### 4.3 额度与计费规则

- 单位：1 credit = ¥0.01，新用户送 500 credits = ¥5。
- 先预扣再结算：一轮开始前预扣一个上限（比如 30 credits），余额不够直接拒绝；结束后按实际成本结算，多退少补。同一用户开两个标签页并发，余额也不会被扣成负数。
- 扣多少：用户扣费 = 本轮成功调用的成本 × 加价倍率（倍率放 flags 表，一期建议 1.0，内测先不赚钱、看真实成本）。
- 校验失败的重写、最终「受阻」的轮次不扣用户钱，但成本照记，算作我们的损耗。
- ¥5 能用多少轮：现在没有 token 日志，算不出来，不编数字。计量上线后跑一周内测，用 llm_calls 的中位数算出「¥5 ≈ N 轮」，再决定赠送额度和定价。
- 防刷：免费额度 + 邮箱注册 = 无限开小号薅额度。所以一期必须是邀请码或手机号，不开放纯邮箱注册。

| 项 | staging | prod |
| --- | --- | --- |

### 4.5 停止开关（四层）

| 层 | 作用 | 触发 |
| --- | --- | --- |
| 全局维护 | 所有用户看到「小谷暂停服务」，后台仍可进 | 后台一键 |
| 单用户封禁 | users.status = suspended，该用户请求直接拒 | 后台用户列表 |
| 单功能开关 | 比如只关模拟面试 | 后台开关页 |
| 自动熔断 | 当日总成本超过 X 元，或 DeepSeek 余额低于 Y 元，自动打开全局维护并提醒 | 定时检查 |

开关每次请求都从数据库读（可加 5 秒内存缓存），改了立即生效，不用重新部署。正在进行的流式回答：当前这一轮让它跑完（已经花了钱，中途掐断用户什么也拿不到），下一轮开始时拒绝。

### 4.9 Agent 页面

结构参照第 1.2 节的三栏：

- 左栏：新建对话、历史会话、底部固定显示剩余 credits 和设置（主题切换在这里）。
- 中栏：对话。三个功能共用一个对话流，入口卡片只是预填起手句并选好模式。
- 右栏（按需展开）：简历成品预览和导出、模拟面试的题目进度和评分、运行过程。不在对话气泡里塞长简历。

配色：现在 `static/index.html` 第 12–14 行已经是 CSS 变量（`--paper`、`--ink`、`--shu` 等）。黑白默认 = 新增一套变量值作为 `:root` 默认，和风那套挪到 `[data-theme="wa"]` 下，用户在设置里切换，存 users.theme。这是换变量值，不是重写页面。

布局细节（栏宽、入口卡片样式、右栏交互、移动端）按 SOP 打样 3–5 个可预览变体再挑，本文档不定死。
