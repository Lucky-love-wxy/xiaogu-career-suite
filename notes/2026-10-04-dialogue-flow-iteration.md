# 多轮对话体验修订 · 启动文档

## 元数据

- 日期：2026-10-04
- 任务名：方向探索不收敛、上下文丢失、格式重复等 9 项用户试用问题
- 所属项目：xiaogu-career-suite（web/）
- 触发类型：debug + 设计（已有项目小迭代：免市场调研节，列适用规范）
- 关联 Principle：feedback_evidence_based_claims

## 现象（用户 2026-10-04 试用，医学生 7 轮方向对话 + 1 轮 JD）

1. 用户输入与小谷回答视觉上难区分。
2. 不是流式输出。
3. Markdown 显示不对；出现“结论 结论”“待核实推断待核实推断”。
4. 方向对话里没有出现牛客/脉脉内容。
5. 已回答“面对消费者”，后面仍问“普通消费者还是患者/家属”。
6. 7 轮后仍没有给出可选的岗位方向。
7. 没贴 JD 的回答里也在讲“招聘说明通常写……”，用户希望 JD 出现前不调用黑话。
8. 每轮格式和开头复述高度重复，不像在跟进对话。

## 复现与根因

| # | 根因 |
|---|---|
| 5、8 | `Session.recent` 只保留最近 2 轮“渲染后文本前 300 字”，大半是模板字；第 1–3 轮的“医学/临床/企业”被截掉。复现：真实模型跑同一序列，第 5 轮上下文里已无“临床”“企业”，模型又问单位类型。 |
| 6 | 方向探索只有提示词“一次问一个缩小问题”，没有收敛条件，模型可以无限追问。 |
| 3 | 前端 `md()` 把每个空行分段都当成新区块（加分隔线）；模型自己在 answer / inference 里写了“结论”“待核实推断”标签。 |
| 7 | 岗位理解不论有无 JD 都把黑话词典命中放进证据包；方向提示词没禁止描述“招聘说明通常写什么”。 |
| 4 | 不是 bug：DeepSeek 本身不联网，实时来源由服务端取；真实抓取未接入（待 Codex Q2–Q4），模拟帖子只覆盖推荐算法岗；方向对话不触发岗位理解。 |
| 2 | 设计如此：先校验再展示，与逐字流式冲突。 |
| 1 | 样式问题。 |

## 适用规范

- 小谷事实边界与输出契约（output-contract.md、phrasing.md）：新增“对话样式”需同步契约与渲染器测试。
- 前端：日式简约，不加装饰。
- 深度分析规范：多轮记忆的数据结构、收敛条件由代码保证，不靠提示词。
- AI 协作 SOP：候选方向是一般性建议，不是结论；由用户选。

## 修法

- 记忆：会话保存全部“小谷的追问 + 用户回答”（不截断）与已知信息表（模型输出 `facts` 由服务端合并）；提示词给出已知信息，禁止重问、禁止复述。
- 收敛：方向回答累计 3 轮后切到 `propose`，必须给 2–3 个候选方向（各一句理由，注明是可选项），服务端校验并保存；下一轮用户按名称或序号选中 → 确定性进入岗位理解并尝试实时来源。
- 黑话：只有证据包里有 JD，或用户明确问某个词时，才放入黑话词典命中。
- 格式：方向 / 一般建议 / 进展三类用“对话样式”：只显示正文和下一个问题，没有真实证据时不显示依据和仍需确认；服务端剥掉模型自写的标签。
- 前端：用户与小谷气泡区分；Markdown 只在固定节标题处分节，支持有序列表。
- 运行日志：web/logs/trace-日期.jsonl（已获用户同意），含用户原话、路由、模型原始输出、最终文本；不含 key 与系统提示词；gitignore。
- 流式：不做逐字流式；可选“阶段进度”另议。

## 验证（2026-10-04）

- 单元测试 65 项通过（新增：7 轮医学对话后提示词仍含临床/企业/消费者/健康消费品；第 3 轮切到给候选、序号选中进入岗位理解并触发实时来源；JD 前不放黑话；模型自写标签被剥掉；对话样式无报告标签）。
- 真实 DeepSeek 复跑用户原对话（n=1）：已知信息表正确累积，第 3 轮给出 3 个候选并编号，“第一个”被代码识别为 MSL 进入岗位理解，回答主动指出 MSL 面对医生而非消费者。
- 无 JD 时“招聘说明通常写……”改为代码拦截后重写。
- 未完全解决：用户补“面对消费者”后重新给的候选仍把 MSL 排第一（模型执行偏差，只有第 3 个面向消费者）；模拟帖子只覆盖推荐算法岗，医学方向的从业者说法显示“没找到”。
- 前端：模拟模型预览验证气泡区分、对话样式、节标题分节；控制台无报错。
