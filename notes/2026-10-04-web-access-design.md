## 1. 市场调研结果

状态：部分已核实；搜索 API 选型与同类产品做法已下发 Codex（notes/2026-10-03-codex-research-brief-live-sources.md Q1、Q2、Q4、Q6），**定稿前必须回填**。

已核实（2026-10-03/04 实测 robots.txt 与未登录访问）：

| 来源 | 对小谷服务器（未列名代理 `*`） | 结论 |
|---|---|---|
| 脉脉 | 全站 Disallow；社区首页、站内搜索跳登录 | 产品运行时不可用；不得冒用放行身份 |
| 牛客 | 只禁 `/search` 等少数路径，有 sitemap | 详情页候选主力，内容页可读性待 Q2 |
| 知乎、小红书 | `*` 全站 Disallow | 不可用 |
| 看准网 | robots 返回前端页面，规则不明 | 待 Q4 |

- DeepSeek API 本身不带联网（文档只给对话接口；是否另有搜索工具未核实，列入 Q6 一并查）。
- 本地 CDP 代理（web-access skill，借用户日常 Chrome 与登录态）技术上能读更多页面，但以用户本人身份访问，该 skill 自身也提示有封号风险。只用于 Codex 做调研，不用于产品运行时。

## 2. 我要解决的问题

方向探索选中岗位后、或理解某个岗位时，小谷需要“同类岗位从业者怎么说”。现在只有模拟帖子（仅推荐算法岗）。要在合规前提下拿到真实、可追溯、带日期的公开帖子。

## 3. 适用的设计规范

- 小谷证据规则（external-research.md）：只读公开页、复述不搬运、每条带链接日期、标适用范围、失败不阻塞。
- 安全：抓回的页面是不可信文本，必须在提示词层之外加行为测试（注入帖）才能上线。
- 端口与凭证：搜索 API key 走钥匙串，不进仓库。

## 4. 方案草案（待 Q2、Q6 回填后定稿）

```text
岗位名 → 搜索 API（site:牛客 等，取前 N 条）→ robots 校验 → 抓详情页（自有 UA，同站 ≥3 秒，缓存 7 天）
       → 提取正文与发帖日期 → 交给模型抽“适用范围 + 要点复述”（同样走编号证据）→ 最多 3 条进证据包
```

- 模块：`web/live_fetch.py`，与现在的 `simulated_live_sources()` 同一接口，模拟环境保留切换。
- 上线前置：Q2（牛客详情页可读）、Q6（搜索 API）、注入帖行为测试。
