# 回答过程可见 · 启动文档

## 元数据

- 日期：2026-10-04
- 任务名：输出内容仍先校验，但把生成过程实时展示给用户
- 所属项目：xiaogu-career-suite（web/）
- 触发类型：设计（已有项目小迭代：免市场调研节，列适用规范）
- 关联：feedback_evidence_based_claims

## 问题

用户要求：“输出的内容可以是经过检验的，但是输出结果的过程我需要一个过程。”现在点发送后只有“小谷在看……”，2–4 秒后整段出现。

## 适用规范

- 先校验后展示：未校验的回答正文不出现在过程里，只在校验通过后整段显示。
- 过程用大白话 + 真实数据（命中几条、哪个来源什么状态、第几次重写及原因），不出现技能名、JSON、内部字段。
- 运行记录面板保留为开发视图，过程视图给用户。
- 前端日式简约，不加装饰动画。

## 方案

- 服务端：新增 `POST /api/chat/stream`，以 SSE 格式逐条推送阶段事件；原 `/api/chat` 保留（测试与脚本用）。
- 阶段：理解问题（规则判断 / 模型判断 / 选中候选 + 结论）→ 查资料库（命中数，或“未贴招聘说明，跳过黑话”）→ 查从业者说法（各来源状态，模拟数据标明）→ 生成回答 → 校验（通过 / 第 N 次没通过及原因）→ 完成（总耗时）。
- 前端：fetch + ReadableStream 读事件，过程逐行出现；完成后折叠为“查看过程（N 步 · X 秒）”。
- 测试：事件顺序；最终文本等于 render() 输出；任何非最终事件里不含回答正文。

## 验证（2026-10-04）

- 68 项测试通过（新增：阶段顺序、回答正文不出现在任何过程事件、重写原因可见、SSE 端点以 final 结尾）。
- 真实 DeepSeek 预览：过程逐行出现（收到 → 理解问题 → 查资料库 → 查从业者说法 → 生成回答 → 校验），完成后折叠为“查看过程（6 步 · 3.1 秒）”，控制台无报错。
