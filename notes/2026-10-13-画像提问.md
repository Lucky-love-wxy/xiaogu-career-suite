# 小谷：主动了解用户基本情况（画像提问）

## 元数据
- 日期：2026-10-13
- 任务名：让小谷在对话里自然地补齐用户基础信息
- 所属项目：xiaogu-launch（小谷线上版）
- 触发类型：设计（已有项目内迭代，涉及新设计决策）
- 关联 Principle：本轮暂停点名
- 来源：用户 10-13 反馈「对话更有智能释放感了，但缺少提问去了解用户基本情况的能力」；截图识别验证时的实测（只贴 JD、没给任何经历，回答却写了「简历可以这样写」）

## 1. 市场调研结果
- 高校就业指导的 intake 表：专业、辅修、预计毕业时间、工作和实习经历、当前职业目标。来源：Kennesaw State 职业教练 intake 表。
- AI 职业助手的接入建议：把学生的专业、毕业年份、职业兴趣作为个性化的基础字段。来源：ibl.ai 指南。另一份 agent 入职脚本按阶段逐个问学历、所在地和工作方式、目标岗位。
- BOSS 直聘：校招身份按毕业时间认定（2026 届春招面向 2025-11 到 2026-10 毕业）。注册流程里填学历、专业、毕业年月、期望城市，这一条是一般认知，没有找到官方帮助页，标「推测」。
- 对话式收集信息的设计经验（slot filling / progressive profiling，多为厂商和从业者文章，不是论文）：
  - 槽位状态放在代码里，由代码负责流程和校验；措辞交给模型。原因：靠模型同时管状态和流程是已知的薄弱点。
  - 每轮只问一个缺的字段，并且禁止模型预告「接下来我还要问……」。
  - 用户一次说了好几样，全部收下，已经知道的不再问。
  - 只问对当前这件事有用的信息，其余的分散到后面的对话里去问。
  - 死板地一项项追问会让人有被控制的感觉。

## 2. 我要解决的问题
- 现状：`Session.facts` 只是模型从用户话里被动抽取，键名随意（「专业」「年级」「我的学校」都有可能）。代码不知道还缺什么，所以不会去问。
- 后果：缺了能决定答案的信息时，小谷不问，而是自己补。最典型的是只贴 JD 时，小谷看不出用户「能不能投」，因为毕业时间、学历、专业不知道。用户没给经历，它就替用户写简历要点。
- 约束：10-12 刚把填表感去掉（不再「用一句话告诉我」、不再强制追问），这次不能加回来。

## 3. 适用的设计规范
- 核心约束：外科手术式改动，只动 agent 的提示词组装和会话状态，不改路由和校验。
- 修改只盯一个点：本轮只做画像提问。
- 事实边界不变：画像信息只来自用户亲口说的话，模型不推测。
- AI 协作 SOP 关键纪律：关键决策点不直接信模型自觉，收敛条件由代码保证（沿用 PROPOSE_AFTER 的思路）。

## 4. 方案
- 基础信息清单（代码里的固定表），每项带别名，用来认出模型写进 facts 的各种键名：
  - 专业
  - 毕业时间（年级、届）
  - 学历
  - 经历（实习、项目、社团；会话里已存了经历或简历也算有）
  - 意向城市
- 按任务决定问哪几项和先后顺序，只问对这件事有用的：
  - 看懂某份 JD（suite 有 J、jd_followup）：毕业时间 → 学历 → 专业 → 经历。判断能不能投要靠这几项。
  - 找方向（direction）：专业 → 毕业时间 → 经历 → 意向城市。
  - 打招呼、聊进展、一般问题（greeting / master / general）：专业 → 毕业时间。
  - 给候选、黑话、改简历、面试：不问。这些任务要么有自己的问题，要么跟画像无关。
- 每轮代码只挑一项还缺的，作为 `<profile_gap>` 交给模型，并写明为什么这一项影响这次的回答。提示语里明确写：
  - 先回答用户这一轮的问题；
  - 只有 next_action 没有更要紧的问题、而且问起来自然时，才用 next_action 问这一项；
  - 一次只问一件事，不预告之后还要问什么；
  - 这一项没弄清之前，不要替用户假设（例如不知道经历就不写简历要点）。
- 提示词里给 facts 规定标准键名，模型抽取时优先用这些键。
- 问过的不再问：小谷的 next_action 里出现这一项的关键词，就记为「问过」，同一会话不再提示，用户不想答也不追。

### 下注
- 决策：画像状态由代码维护，模型只负责问的措辞和时机。
- 可验证的预期：对话回归第 4 段（贴 JD → 「我是应届生，这个能投吗」）里，小谷会问毕业时间或学历，而不是直接下结论；5 段对话都不出现「用一句话告诉我」，也不会一轮问两个问题。
- 验证方式和日期：10-13 用真实接口跑对话回归 round7，逐段人工读。

## 回填
- 实施（web/agent.py）：
  - 新增 PROFILE 清单、按任务的提问顺序、profile_gap / profile_known / profile_reask；
  - Session 新增 profile_asked 和 profile_asked_turn 两个字段（数据库按字段名存取，不用迁移）；
  - 提示词里加入可选的 `<profile_gap>`；facts 规定标准键名；
  - 聊天说话方式补两条：一次只问一件事，问过、说过的不再问。
- 真实接口迭代 4 轮（evals/dialogue/2026-10-13-round7 到 round10）：
  - round7：会问了，但出现三类问题：
    - 用户只是在问问题，小谷也连着两轮各问一项；
    - 「应届生」被模型记成「学历」，代码误以为学历已知；
    - 第 5 段 next_action 把原有问题和画像问题拼成了两问。
    - 修法：问过一项后隔一轮再提示；学历只认本科、硕士这类词；提示里写明 next_action 只能一个问题。
  - round8–9：模型仍会一字不差地重问自己问过的问题，用户说了「应届生」还问「哪一届」，提示词压不住。修法：代码拦截，next_action 去问已问过或已知道（含这一轮刚说的）的那一项，就判不通过、让模型重写。
  - round10：5 段都没有再重复问基础信息。第 1 段在合适的时机问了专业和届别；第 2 段问过专业后改问「投哪类产品」；第 4 段说了「应届生」后不再问届别；黑话那段没有插画像问题。
- 下注验证：「第 4 段会问毕业时间或学历」部分成立。round7 是贴 JD 那一轮就问了届别；round10 那一轮没问，用户自己说了「应届生」后也没再问，第 3 轮问了专业。「不出现『用一句话告诉我』」成立。「不一轮问两件」round10 成立。
- 测试：162 通过（新增 11 个；旧测试 test_screenshot_sentences_reach_model_not_canned_menu 的第二轮假回答改成了另一个问题，原因是重复问专业现在会被拦）。
- 遗留：
  - 非基础信息的问题，用户没回答时，小谷下一轮会换个说法再问（round10 第 5 段「投的哪类岗位」），本轮不处理。
  - 第 4 段第 3 轮代码提示的是「学历」，模型问的是「专业」：代码只能管问不问、不问什么，管不了模型选哪项。
