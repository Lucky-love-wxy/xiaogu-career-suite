## 3. 适用的设计规范
- 前端风格：沿用现有两套主题变量，卡片用现有 `.mi`、`.menu-pop` 的视觉语言，不新加颜色。
- 事实边界：卡片内容是用户本人填写的事实。期望薪资只作为用户偏好记录，小谷没有薪资数据，不判断薪资合不合理，也不给数字。
- 隐私：卡片按用户长期保存。隐私政策要补一句「基本情况卡片的保存和删除」，用户可以随时清空。
- 回归：每条标注都写成 run_dialogues.py 的自动检查。

## 4. 方案
- 数据：新增 `user_profile` 表（user_id → JSON），存取接口为 `GET/POST /api/me/profile`；提交空卡片即清空。
- 卡片字段（只有专业和毕业时间必填，其余可选）：
  - 学校
  - 学历（大专 / 本科 / 硕士 / 博士）
  - 专业
  - 毕业时间（届别）
  - 意向城市
  - 城市偏好（一线 / 新一线 / 二线及以下 / 家乡附近 / 都可以）
  - 单位类型（大公司 / 中小公司 / 初创 / 国企央企 / 事业单位 / 外企 / 都可以）
  - 期望月薪（不确定 / 区间）
  - 经历（实习、项目、社团、比赛，自由填写）
  - 感兴趣的方向（可选）
- 运行时：
  - 每轮把卡片内容放进会话（`Session.profile`），作为已知信息给模型；画像清单把卡片也算作已知；
  - 找方向时卡片没填，就回复「先填卡」并附打开卡片的按钮；
  - 卡片填好提交后，自动发一句「我填好了基本情况」，直接给第一批候选。
- 候选提示词：经历少时，先推荐能入门的岗位，并说明往上走的路径；候选要对应卡片里的城市和单位类型偏好。

### 定下的实现约束（10-14 复核后）
1. 卡片不放进会话状态。只存在 `user_profile` 表里；每轮由 `platform.run` 读出，作为参数传给 `agent.handle`，用于拼提示词和判断「已知」。原因：会话状态会整份存进 `chat_sessions.state`，放进去的话每个对话都留一份副本，清空卡片清不干净。用测试保证清空后 state 里没有卡片内容。
2. 「先填卡」的门槛看合并后的已知信息：卡片加上聊天里说过的，专业和毕业时间都知道就放行。不填卡、直接在聊天里说清的用户不会被挡；一直不填的，由现有的 repeat_guard 兜底。
3. 卡片提交后自动发的那句话（「我填好了基本情况，帮我看看能往哪些方向走」），由规则直接路由到给候选，不经过分类器。卡片已填时，第一次进找方向就直接给候选；之后仍走原来的「候选还在桌上就按新偏好重给」逻辑，不会每轮都出一批。
4. 只留一条收集路径。没填卡时，10-13 的画像提示不再逐项问专业、届别，改为引导用户填卡片，每个会话只引导一次；填了卡，缺的项也不在聊天里追问。
5. 段落长度只写进提示词，加上回归自动检查；运行时不硬拦，避免为了排版让整轮受阻。
6. 「打开卡片」的信号用返回字段 `action`，不放在 trace 里（生产环境会删 trace）。
7. 期望薪资只用来理解偏好，提示词里写明不在回答里复述数字；先查现有数字和薪资校验规则，避免冲突。
8. 结尾去句号放在 `_finish` 渲染之后，只去掉整段最后一个「。」。

### 下注
