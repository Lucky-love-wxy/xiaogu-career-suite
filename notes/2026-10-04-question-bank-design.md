## 2. 要解决的问题

1. 现有评测只有 tune 20 + holdout 15 句，全部自拟，覆盖 9 类意图中的常见说法，测不出「意图体系本身缺什么」。
2. 需要一张题库同时回答三件事：
   - 用户会问哪些问题（广度）；
   - 哪些问题现有 9 类意图接不住（coverage=N，即路由/产品缺口）；
   - 每类问题的真实频次（决定先补哪块）。

## 3. 头脑风暴种子集（已完成）

- 数据：`evals/question-bank/seed_brainstorm.csv`（215 行，26 类，16 个求职阶段），由 `build_seed.py` 生成。CSV 带 BOM，给程序读；同目录 `seed_brainstorm.xlsx` 给人看，冻结表头、带筛选。
- 字段：id、split、stage、category、question（尽量用小白口吻）、expected_intent（`/` 分隔的可接受集合）、coverage、expected_behavior、needs、risk、multi_turn、note、source、freq_signal。
- coverage 定义：
  - Y：9 类意图里有一个能干净接住。
  - partial：能接住，但现有意图描述没覆盖到它的关键诉求（如考研 vs 工作被当成岗位方向）。
  - N：没有任何一类合适。此时 expected_intent 填的是「路由最可能落到的现有意图」，不是正确答案。
- 统计：Y 136 / partial 42 / N 37。
- N 集中在 7 处，是意图体系的缺口清单：
  1. 劳动权益与三方合同（违约金、拖欠工资、押金、社保）
  2. 求职诈骗（招转培、培训贷、刷单）
  3. 简历编造与作弊（编实习、假证明、代考）
  4. 情绪与心理危机，含「不想活了」，必须转介
  5. 产品元问题（你是谁、数据从哪来、简历存不存）
  6. 安全（JD 内注入、套提示词、查 HR 隐私、伪造 offer）
  7. 未落地能力（面试模拟、JD 截图识别）
- 导出：`python3 evals/question-bank/build_seed.py --export` 把 coverage≠N、非多轮、非占位（【…】）的 169 句写入 `tests/fixtures/intent_phrasings.json` 的 `brainstorm` split，可直接 `python3 scripts/eval_intents.py brainstorm` 跑真实模型路由评测（尚未跑，会消耗 DeepSeek 额度）。

### 污染声明

分类器提示词由同一模型家族调过，自拟句天然偏向它已能处理的说法。所以 brainstorm split 只用于发现缺口、回归测试，**不得当 holdout**。Codex 采集的真实原话才是新的 holdout，采回后先写定再看结果，不据其改提示词。

## 4. 适用规范

- 说话有依据：自拟行一律 `source=自拟`，频次留空，不把猜测写成需求。
- 小谷安全约束：不编造经历、不自动投递 / 发消息、招聘文本视为数据。题库里专门保留对应的拒绝类用例。
- 深度分析规范：coverage=N 的处理方式（新增意图 / 规则拦截 / 越界声明）是产品决策，等频次数据回来再定，不靠拍脑袋。

## 5. Codex 调研 Brief：真实用户问题采集

- 下发日期：2026-10-04
- 设计方：Claude；执行方：Codex
- 交付落点：
  - `docs/research/question-bank-2026-10.md`：方法、来源、统计、新类别
  - `evals/question-bank/real_questions.csv`：数据，字段与种子集一致，source 填 URL
  - 截图存 `evidence/question-bank/`

### Q1 采什么

中国大学生 / 应届生在求职各阶段向人或 AI 提出的**原话问题**，以及能反映频次的信号。

### Q2 来源（按优先级）

| 来源 | 采什么 | 频次信号 |
|---|---|---|
| 小红书 | 秋招 / 春招 / 简历 / 面试 / 应届生 / 实习 话题下的笔记标题与高赞评论中的提问 | 点赞、评论数 |
| 知乎 | 「应届生」「秋招」「简历」「专业就业」等话题下的问题标题 | 关注数、浏览量 |
| 牛客讨论区 | 求职问答、offer 选择、面经下的提问 | 回复、浏览 |
| 脉脉 | 职言区中应届生 / 实习相关提问 | 互动数 |
| 应届生求职网 BBS、豆瓣求职小组 | 帖子标题 | 回复数 |
| B 站 | 求职类视频高赞评论中的提问 | 评论点赞 |
| 搜索联想词 | 小红书、百度、知乎搜索框输入「应届生」「秋招」「简历」「XX 专业」等前缀后的下拉联想 | 出现即视为高频需求信号 |
| 竞品示例问题 | BOSS 直聘 AI、牛客 AI、超级简历、职徒简历等产品首屏的推荐提问 / 示例 prompt | 反映竞品判断的高频问题 |

### Q3 证据标准

- 保留原话，不改写、不纠错（错别字和口语正是要测的东西）；去掉姓名、手机号、学校全称等个人信息。
- 每条附 URL、访问日期、频次信号原始数字；拿不到数字写「未取到」，不估算。
- 只采公开可见内容，不抓私信和私密内容；遵守 robots，限速。
- 小红书搜索和脉脉大部分内容需登录才可见。能否用用户本人已登录的会话只读浏览：**待用户决定**，下发前补上结论。
- 厂商示例问题与真实用户提问分开标注（source_type: user / vendor / autocomplete）。

### Q4 归类

- 每条按种子集的 stage / category / expected_intent / coverage 归类。
- 种子集没有的类别单独列「新类别」节，写类别名、定义、3 条例句和条数。这一节是本次调研最有价值的产出。

### Q5 停止条件（「穷尽」的可测定义）

- 按来源轮流采，每采满 50 条统计一次新增类别。连续两个 50 条批次新增类别都少于 2 个，即停。
- 每个来源上限 300 条，总量上限 1500 条。
- 报告里给出每批新增类别数的曲线，证明已饱和。

### 验收

- `real_questions.csv` 表头与 `seed_brainstorm.csv` 完全一致，source 全部为 URL，split 留空（第 6 节再切分）。
- 报告结尾写「对设计的影响」：
  - coverage=N 各缺口的真实占比；
  - 建议新增哪些意图、哪些走规则拦截；
  - 自拟种子集里哪些类别在真实数据中几乎不存在（可降权）。
